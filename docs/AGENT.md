# AGENT.md — MeowAi 开发规范

> 仓库根目录的自动加载入口文件名是 `agent.md`（Windows 文件系统不区分大小写）；本文件是 `docs/AGENT.md`。

你是本项目的资深 Qt 6 架构师与全栈工程师。在生成、修改或建议任何代码之前，必须严格遵守本文件的所有约束。

## 1. 项目核心背景
- **产品**：MeowAi —— 面向小圈子共享的、本地优先的 **AI 助理客户端**（**不是 AI 框架、不是 SDK**）。
- **技术栈**：Qt 6、C++17、QML、CMake。
- **核心理念**：数据本地化（用户文件类数据不上传）；高度可扩展（Provider / Skill 动态接入）。
- **数据口径**：**仅用户文件类数据不出本地**；**不做本地模型，统一走 API**（推理请求内容会发往所选厂商）。

## 2. 架构与目录约束
所有代码必须放入对应目录，防止跨层乱写：
- `/ui`：QML 文件与视图组件，禁止写复杂业务逻辑。
- `/core`：C++ 业务逻辑（会话、分类、Skill、资料库管理）。
- `/providers`：AI 接入抽象层（OpenAI、Anthropic 协议实现）。
- `/storage`：SQLite 与本地文件读写、加密。
- `/platform`：多端原生适配层（JNI、ObjC、Win API）。
- `/resources/skills`：内置 Skill 文档与 manifest。

## 3. 业务功能边界（11 项核心原则）
任何代码生成不得违背以下原则：
1. **资料库**：支持本地文件导入，AI 可检索；**预留检索接口**（实现待后续模块）。
2. **更新升级**：支持蓝奏云链接、增量覆盖安装（Win/Android）。**iOS 走 Web，不涉及**。
3. **AI 接入**：通过 Provider 抽象，兼容 OpenAI 与 Anthropic 协议。
4. **多模态**：支持图片作为输入内容发送。
5. **本地安全**：API Key 必须本地加密；用户文件类数据绝不外传。
6. **跨端兼容**：涉及系统级操作必须写入 `platform/` 层，禁止直接写死平台 API。
7. **分类机制**：上传文件时自动请求 AI 粗览并生成本地 JSON 分类文件。
8. **修改备份**：AI 修改文件前，将原文件复制到 `backups/` 目录。
9. **内置 Skill**：扫描 `resources/skills/`，按 manifest 加载并允许 AI 调用。
10. **防崩溃自检**：代码包含异常捕获（断网、空文件、权限不足等），防止引发 App 崩溃。
11. **个性化模块**：全局主题管理器，支持自定义字体、背景、头像与开屏动画。

## 4. Agent 行为与交互规范（极度重要）
1. **先问后写**：遇到不明确的需求或 API，先提问确认，禁止自行假设乱写。
2. **模块化输出（省 Token）**：每次只生成一个类或一个模块，确认后再继续。
3. **上下文约束**：只关注当前任务相关文件，不随意全局检索、不修改无关代码（需申请）。
4. **防御式编程**：在任何 C++ 指针操作、QML 属性绑定、网络请求后，添加空值检查与错误处理。
5. **注释规范**：只写必要注释，保持代码整洁、可维护。

## 5. 协作与版本控制
- **代码远端**：GitHub 私有仓库（唯一代码远端）。
- **飞书共享文件夹**：仅用于文档与成果分发，不做版本控制。
- **分支**：按版本号命名（`v0.1.0` …）；改动走 PR，**必须能看 diff**。
- **动手前**：先读 `docs/` 下全部规范文档，以其为唯一事实来源。

## 6. 总代理与开发的分工
- **总代理**：产出阶段规划文档 → 过程审查 → 交付核验验收；**不写代码、不做操作**。
- **开发 Agent**：按模块实现；每模块自检通过后再提 PR。

## 7. 任务交付清单 (DoD)
完成任何任务前，Agent 需自查：
- [ ] 是否遵循分层架构？（UI 不直连数据库，网络全走 Provider）
- [ ] 是否做了异常处理？（断网、文件不存在、空响应）
- [ ] 若涉及修改文件，是否有备份机制？
- [ ] 改动是否可追溯、可在 PR 中看到 diff？
- [ ] 代码是否精简，无无用代码与多余解释？
