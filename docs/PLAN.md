# MeowAi 开发计划 (Plan)

> 依据 `PROJECT_CHARTER.md`；如有冲突，以 `PROJECT_CHARTER.md` 为准。
> 唯一事实来源：`docs/` 目录下的规范文档。

## 1. 团队与协作基建
- **团队**：3 名开发，各自配备 Agent（**Agent 类型可能不同**）。
- **代码版本控制**：**Git + GitHub 私有仓库**（唯一代码远端）。
- **飞书共享文件夹**：**只用于文档与成果分发**，不承担版本控制。里程碑可将某个可运行版本整份快照留档。
- **分支**：按版本号命名（如 `v0.1.0`、`v0.2.0`）。
- **合并与评审**：走 PR；不接受"无 diff、不可追溯"的改动。
- **多端**：使用 Git Worktree，为 Win / Android 建立独立工作树；**可能多人并行**，注意合并冲突。
- **Demo**：保留可实时跑通的 `demo` / `dev` 分支，避免影响主线。

## 2. 角色分工
- **开发**：3 人 + 各自 Agent，负责编码实现。
- **总代理（Project Agent）**：产出各阶段**规划文档** → 过程**审查** → 交付**核验验收**；**不写代码、不做操作**。

### 阶段二：核心基础模块
- [x] **安全机制**：API Key 本地加密存储。
- [x] **个性化模块**：全局主题引擎，实现自定义字体、背景切换、开屏动画及头像上传。
- [x] **AI 接入**：实现 OpenAI 与 Anthropic 协议请求，支持多模态图片上传。
- [x] **资料库与分类（RAG，分支 `v0.2.5`，一次性交付）**：小库管理（一个文件可属多库；**删除库 / 解除关联绝不删用户原文件**）；上传导入（复制）+ 关联文件夹（引用，快照 + 手动重建）；**文本类解析** txt / md / csv / json / PDF 文本层 / docx / xlsx / pptx，**图片类** jpg / png / webp 等走**多模态模型生成描述（caption）**入库（不做本地解析）；统一为**带元数据的结构化文本**（表格转 Markdown、保留页码 / 工作表 / 行号 / 图片序号）；chunk + **向量入库**（embedding 走 API，可复用对话 Key，缺失时**延迟索引**）；检索含**每文件片段上限 + 邻居扩展**，并以 **FTS5 关键词兜底**；**K 值 / 每文件上限 / token 预算均可配置**；对话端**手动选库 + 库内自动检索**，**回答必须列出引用来源**；**首次启用需明确同意内容外发**、**给出成本预估**。**不在本次**：视频（仅预留接口）、网页抓取、AI 写回文件（只读）、rerank / 多轮检索 / 分层摘要。
- [ ] **防崩溃自检**：对上述模块做异常边界测试，确保无崩溃（已随安全 / AI / 会话历史部分交付；待资料库完成后补齐）。

## 4. 任务交付标准 (DoD)
任何任务（含功能模块）在标记"已完成"前，必须满足：
1. 代码通过本地编译与基础单元测试。
2. 经过手动异常流测试（空数据、断网、超大文件等），确认不引发 App 崩溃。
3. 通过人工 Code Review / 结对检查（**PR 中必须能看到 diff**）。
4. 涉及的改动可追溯（有提交、有说明）。
