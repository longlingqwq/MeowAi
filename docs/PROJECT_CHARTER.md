## 0. 本版关键澄清（务必先读）
- **MeowAi 是面向用户的产品——一个"AI 助理客户端"，不是"AI 框架"、不是 SDK。**
- 原文档中「本质：纯框架」这句话，是**写给下一步开发 AI 的指令**：因为下一阶段要完成的是"**框架搭建**"这个**开发动作**，而非对产品定位的描述。**不得**据此把产品理解成框架或 SDK。

## 1. 项目概述
- **产品名**：MeowAi
- **定位**：面向**小圈子共享**的、**本地优先**的 AI 助理客户端；带自有资料库，能"懂相应知识"，形态是"有自己知识库的 AI 助理"。
- **形态本质**：AI 助理客户端（应用）。**不是 AI 框架。**
- **差异点**：① **个性化**（字体 / 背景 / 开屏动画 / 头像）；② **移动端适配**。
- **使用模型**：小圈子共享 = **每人各自一份独立数据**。即**单用户、本地数据模型**，**无共享知识库、无账号体系**。
- **数据口径（重要）**：「数据不出本地」**仅指用户文件类数据**（资料库、分类、备份、Skill、个性化资源、API Key）保存在本地；**不做本地模型，统一走 API 方案**。因此对话请求内容会发送给用户所选模型厂商——**此点已被接受**。

## 3. 端与平台策略
- **Windows / Android**：原生客户端（Qt）。
- **iOS**：**只提供网页端，不提供安装包**。→ 因此"蓝奏云链接下载并覆盖安装"在 iOS 上**不适用**，该矛盾随之消除。
- **Web 端**：既是预留方向，也是 **iOS 用户的唯一入口**。
- 面向端：Win / Android 原生 + Web。所有系统级差异写入 `platform/` 层，禁止写死平台 API。

## 4. 技术栈与开发环境
- **框架**：Qt 6.x + CMake
- **语言**：C++17 + QML（前端 UI）
- **存储**：SQLite（元数据/索引）+ 本地文件系统（资料/备份/分类/Skill/个性化资源）
- **网络**：Qt Network（AI API 请求、更新检查）
- **安全**：系统级 Keychain/Keystore 保存敏感 Key

## 5. 底层架构设计（预留拓展）
- **UI 层 (QML)**：纯展示与交互，不写复杂业务逻辑；全局主题管理器统一控制字体/背景。
- **逻辑层 (Core)**：模块化为 资料库管理、AI 引擎、Skill 注册器、更新管理器、个性化配置中心。
- **平台适配层 (Platform)**：隔离多端差异（路径、网络、安装器）。
- **存储层 (Storage)**：SQLite + 本地文件读写 + 加密。
- **拓展接口**：Provider 抽象（便于新增 AI 厂商）；Skill 抽象（支持动态加载本地扩展）。
- **预留**：资料库**检索接口**——即使实现方式待定，架构也需预留，避免后续推翻重构。

## 6. 本地存储结构
```
<AppData>/
  config.json     # 模型配置（Key 加密）与个性化配置（字体、背景路径）
  library/        # 资料库原始文件
  categories/     # AI 生成的分类文件 (.json)
  backups/        # AI 修改前的备份文件
  skills/         # 内置 Skill 文档 (.md + manifest)
  assets/         # 用户自定义资源（头像、背景图、字体库）
```
