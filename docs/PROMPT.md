## 本次范围（**只做以下两块**）

### 模块一：安全机制 —— API Key 本地加密存储
- 落地 `SecureStore` 的**真实实现**（替换当前恒返回 `false` 的占位）。
- Key **本地加密存储、绝不明文落盘、绝不上传**；按平台实现：Windows 用 DPAPI/系统凭据，Android 用 Keystore，Web 明确不可用/降级提示。
- 支持**多 Provider 各自独立的 Key**（OpenAI / Anthropic）；提供 `has / save / load / erase`。
- 修正 `isAvailable()` 语义，避免上层**误以为"已加密安全"**。
- 异常边界：Key 文件缺失 / 损坏 / 权限拒绝 → **不崩溃**、返回明确错误。
- 补单元测试 + 异常流测试。

### 模块二：AI 接入 —— 真实协议请求 + 多模态
- `OpenAiProvider`：实现**真实** Chat Completions 请求（含 **SSE 流式**）。
- `AnthropicProvider`：实现**真实** Messages API 请求（含流式）。
- 统一并扩展 `ChatTypes`：消息、role、内容块（文本/图片）、usage、结构化错误类型。
- 网络统一走 `QNetworkAccessManager`、异步；**`cancel()` 必须真正中断在途请求**。
- **多模态**：支持图片输入（base64），适配 OpenAI 与 Anthropic 各自格式。
- 错误处理：401 / 429 / 超时 / 断网 / 流中断 / 空响应 → 结构化错误信号，**不崩溃**。
- **安全**：Key 只从 `SecureStore` 读取；**日志脱敏**——禁止打印 Key 或完整请求体。

## 硬性约束
- **分层**：UI(QML) 不写业务逻辑；网络全走 `providers/`；系统级操作只进 `platform/`。
