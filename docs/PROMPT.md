## 1. 本次目标（一句话）

把资料库从"只注入 Top-K 片段"升级为**"文件级召回 + 全文/章节注入"的参考资料模式**：
先定位相关**文件**，小文件注入**全文**，大文件注入**相关章节**，预算不足时回退片段；
同时把 prompt 从"必须依据资料回答"改为"资料仅供参考"。

## 2. 核心背景（必须理解，避免误实现）

- **现有实现**：`RagRetriever` 只做片段检索（`topK` / `perFileLimit` / `tokenBudget`），`ChatController` 只把 `RetrievalResult.chunks` 装配进请求。**没有任何文件级注入。**
- **FTS5 关键词索引从不发给模型**：它只是本地搜索兜底，返回的仍是片段原文。
- **大模型 API 是无状态的**：每次请求独立，服务端不保留上一次内容。
  - **禁止**把方案设计成"服务端记住上次发的文档"。
  - 能做的只有：① 只有本轮判定相关才注入；② 文档放在**稳定前缀、稳定顺序**，提高厂商 prompt caching 命中率；③ 用预算控制规模。
  - 在文档/注释中**不得**声称"发一次后不用再发"。

## 3. 必做范围

### 3.1 文件级召回

1. 复用现有向量检索 + FTS5 兜底，但结果**按文件聚合打分**：
   `文件相关度 = max(片段相似度) + 命中片段数 × 权重`（权重可配）。
2. 达到阈值才判定为"相关文件"；按相关度排序。
3. 挂载小库后**自动**执行（无需用户每次点选），但**只有相关文件才注入**。

### 3.2 注入粒度（三级，逐级降级）

| 级别 | 条件 | 行为 |
|---|---|---|
| **全文** | 文档 token ≤ 单文件预算（默认 **20000**） | 按 chunk 顺序拼接全文，**去除重叠**（相邻 chunk 有 overlap 时必须去重） |
| **章节** | 文档超预算，且能识别章节 | 按章节内最高片段相似度排序，依次取章节直到预算用尽 |
| **片段** | 章节识别失败 / 预算仍不足 | 回退现有片段模式 |

- 每一级降级都**必须在 UI 与回答中明确提示**，禁止静默截断。
- 多文件：按文件相关度排序依次装入，直到**全局预算**（默认 **100000**）用尽。
- 回答中须标明：用了哪些文件、每个文件是全文/章节/片段、是否被截断。

### 3.3 章节识别

有结构用结构：
- docx：标题样式（Heading 1/2/3）
- markdown：`#` 层级
- PDF：书签 / 目录（Outline）
- xlsx：工作表
- pptx：页标题

**无结构时**（无书签 PDF、扫描件）：按"页"或"固定块"近似——**在 UI 中注明这是近似切分**。

### 3.4 提示词语义改造（关键）

当前是"根据以下资料回答"，必须改为：

> 以下文档**可能与用户的问题相关，仅作为参考**。
> 你**不必**仅根据这些文档回答，可以结合你自身的知识，也可以使用联网搜索的结果。
> 若使用了文档内容，请标注来源（文件名 + 页码/工作表/行号）。
> 若文档未提及，请明确说明"资料库中未提及"，再用其他方式回答。

**禁止**出现"只能依据资料回答""资料中没有就不能回答"这类约束。

### 3.5 预算与自动检测

- 单文件预算：**默认 20000**，滑块可调（建议范围 5000–50000）。
- 全局预算：**默认 100000**，可配。
- **自动检测**：`resources/providers.json` 目前**没有 `contextWindow` 字段**，必须为每个模型补上（以官方文档为准，附出处）。
- 实际预算必须取：
  `effective = min(用户设定, 模型 contextWindow - 历史消息估算 - 回答预留)`
- 超出上下文窗口时**自动降级到章节级**并提示，**不得**发出会报 400 的超长请求。

### 3.6 UI 与可观测性

1. 每次提问后显示：**相关文件列表、注入级别（全文/章节/片段）、注入 token 数、是否截断**。
2. 资料库面板提供滑块：单文件预算、全局预算。
3. 显示当前模型的上下文窗口与"实际可用预算"。
4. 保留既有引用来源展示（文件名 + 定位）。

## 4. 数据模型变更

现有只有 `chunks`，需补充：

- `documents`：抽取后全文（本地文件路径或 TEXT）、token 估算、章节结构来源（书签/标题/工作表/无）。
- `sections`：所属文档、章节路径、起止 chunk、token 估算、序号。

要求：
- **复用既有 SQLite `Database`**，走既有 schema 迁移机制，不新建存储。
- `chunks` **保留**，继续用于召回与引用定位。
- 现有用户数据必须能平滑迁移，不得要求重装或重建库。

## 5. 明确不做

- 视频（仅保留既有预留接口）。
- 网页抓取（联网搜索已有，不改）。
- AI 写回/修改文件（资料库仍只读）。
- rerank、多轮自主检索、跨文件分层摘要（后续阶段）。
- 本地模型。
- 服务端会话记忆 / 厂商托管会话。

## 6. 验收标准 (DoD)

1. 本地 Debug 构建通过，`ctest` 全绿；新增单测覆盖：文件聚合打分、全文拼接去重、章节选择、预算截断、上下文窗口钳制。
2. 挂载小库后提问：**相关文件自动注入**；不相关时**不注入**且不报错。
3. 小文件走全文、大文件走章节、无结构走页级近似，三级切换均有可见提示。
4. 文档超出上下文窗口时自动降级，**不产生 400**，不崩溃。
5. 回答可结合自身知识/联网搜索；使用文档时标注来源；文档未提及会明确说明。
6. 预算滑块生效并持久化；重启后保持。
7. 异常流手测：空库、损坏文件、超大文件、断网、无 embedding Key、无结构 PDF——均不崩溃。
8. 走 PR，diff 可见；完成后在 `docs/DEVLOG.md` **追加**一条记录。
