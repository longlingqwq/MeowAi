# MeowAi 开发工作流 (Workflow)

> 依据 `PROJECT_CHARTER.md` 与 `PLAN.md`。本文件定义"怎么协作、怎么算完成"。

## 一、规划阶段（SDD 驱动）
1. **需求对齐**：提出需求后，由 AI 辅助提问，确认真正的用户痛点与技术边界。
2. **规范文档**：遵循 SDD (openSpec) 原则，产出**可修改**的规范文档，并统一放于 `docs/`。
3. **技术栈确认**：锁定 Qt / C++17 / QML / SQLite 等环境。
4. **生成 Plan**：产出带阶段目标、且包含防崩溃交付标准的开发计划。
5. **总代理介入**：总代理产出该阶段**规划文档**并据此**审查**，方案确认后方可开发。

## 二、开发阶段（AI 辅助 + Git 协作）
1. **仓库与远端**：
   - 代码版本控制 = **Git + GitHub 私有仓库**（唯一代码远端）。
   - **飞书共享文件夹** = 文档与成果分发（不做版本控制）。
   - 配置 `.gitignore`，建立基础分支保护规则。
2. **版本与 Demo**：分支按版本号命名（`v0.1.0` …）；维持一个持续可运行的 Demo 用于实时测试。
3. **架构先行**：底层架构必须预留拓展接口（主题引擎、Provider 抽象、**资料库检索接口**），避免后期重构。
4. **模块化开发**：
   - 功能拆为独立模块（资料库、AI 接入、个性化、Skill）。
   - 严禁让 AI"一把梭"；每次只提供**当前模块**的上下文，节省 Token。
5. **积极自检与防崩溃（核心红线）**：
   - 完成一个功能/模块后**严禁直接交付**。
   - 必须在 Demo 分支做自检，重点覆盖异常边界，**防止 Bug 与崩溃**。
   - 通过"AI 自动测试用例跑通 + 人工点击无闪退"后，再提 PR。
6. **增量升级开发**：Win/Android 开发直接覆盖升级逻辑（对接蓝奏云下载），无需卸载重装；**iOS 走 Web，不涉及安装包**。
7. **Worktree 多端开发**：各端拉取独立 worktree 文件夹开发，隔离上下文；个性化资源路径需单独适配。**多人并行时以 PR 合并为准。**

## 三、评审与验收阶段
1. **PR 评审**：改动必须可追溯、可看 diff；无 diff 的改动不接受。
2. **总代理审查与验收**：对照 `PLAN.md` 的 DoD 逐项核验；不满足即打回。
3. **Bug 测试**：全链路验收，专盯高频操作与个性化设置的稳定性。
4. **压缩整合**：发布包前的代码清理。
5. **打包发布**：图标与 UI 定稿，规范命名，制作安装程序 / 构建 Apk。

## 四、AI 协作省流策略
- **模型分配**：规划 / 架构 / 难 Bug 用高级模型；UI / 基础逻辑用轻量模型。
- **规则约束**：在仓库规则文件（如 `.cursorrules` / `AGENT.md`）中写明"**先读 `docs/` 下的规范再写代码**"。
- **防崩提示词**：写代码时附带指令"请考虑空指针、越界、网络异常等边界情况，确保代码健壮不崩溃"。
- **跨对话连续性**：结论必须落成 `docs/` 内文档——所有对话、所有 Agent 以此为事实来源，换人/换 Agent 也不跑偏。
